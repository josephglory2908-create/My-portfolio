PostgreSQL · Database reporting

DVD rental performance analysis

Reusable SQL reporting that transforms transactional rental data into a film- and category-level summary for business analysis.

01 / Business question

Which films and categories generate the most rental activity?

The analysis creates a structured report for evaluating film popularity, category demand, customer reach, rental recency, and whether individual rentals were returned.

02 / Data model

Six source tables, one reporting workflow.

The project connects rental transactions to inventory, films, categories, and customers using relational joins.

rental→inventory→film→film_category→category+customer

03 / Technical approach

From raw transactions to a refreshable report.

  1. Classify rental status

    A PL/pgSQL function converts null and populated return dates into clear “Not Returned” and “Returned” labels.

  2. Build the detailed layer

    A multi-table query captures rental, film, store, customer, date, category, and status fields for the latest three-year window.

  3. Aggregate the summary

    Grouped calculations produce total rentals, unique customers, first rental date, and last rental date by film and category.

  4. Automate report maintenance

    A statement-level trigger rebuilds the summary after inserts, while a stored procedure refreshes the detailed report from its source tables.

05 / Business value

A repeatable foundation for inventory and demand decisions.

The reporting structure supports questions about title popularity, category performance, customer reach, and recent rental activity. Scheduling the refresh procedure with pgAgent could keep the report current for recurring review.
